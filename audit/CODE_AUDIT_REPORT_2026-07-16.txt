4) High-Confidence Duplicate/Overlap Findings

4.1 Duplicate Python modules with overlapping responsibility (High)
- scan provider duplicated:
  - robot_ui/scan_data_provider.py
  - ui_qml/robot_ui/scan_data_provider.py
- Evidence:
  - Both define class ScanDataProvider and near-identical API surface (getBasePoints/getActualPoints/getAllRowData/etc).
  - Runtime uses ui_qml/robot_ui/scan_data_provider.py (imported in ui_qml/main.py).
- Risk:
  - Bug fixes can land in wrong copy (already observed with getAllRowData mismatch earlier).

4.2 Duplicate plot item modules (High)
- scan plot item duplicated:
  - robot_ui/scan_plot_item.py
  - ui_qml/robot_ui/scan_plot_item.py
- Evidence:
  - Both define class ScanPlotItem and same core methods (loadFromProvider, pickPoint, paint, rendering pipeline).
- Risk:
  - Divergent behavior between copies; difficult debugging.

4.3 Backend mock/real/base appear copy-equivalent (High)
- Files:
  - robot_ui/backend/robot_backend_base.py
  - robot_ui/backend/robot_backend_mock.py
  - robot_ui/backend/robot_backend_real.py
- Evidence:
  - All define class MockRobotBackend with same method set (__init__, tick, get_robot_io).
- Risk:
  - Naming/structure implies abstraction but implementation does not yet differentiate real vs mock.

4.4 EtherNet/IP stack overlap across multiple implementations (High)
- Overlapping protocol implementations in:
  - ui_qml/robot_comm/robot_comm_bridge.py
  - ui_qml/robot_comm/fanuc_eip_driver.py
  - ui_qml/robot_sim.py
  - ui_qml/RobotUI/adapter.py
- Evidence:
  - Repeated low-level helpers and loops: _encap_header, _register_session, _build_forward_open, _process_io_data, UDP RX/TX loops.
- Risk:
  - Protocol fixes may be patched in one implementation and missed in others.

4.5 QML screen variant duplication (High)
- Cell status duplication:
  - ui_qml/RobotUI/screens/CellStatusScreen.qml (used in Main.qml)
  - ui_qml/RobotUI/screens/CellStatusScreen_4.qml (not referenced by Main.qml)
- Evidence:
  - Repeated function families: loadAlarmCatalog, rebuildAlarms, stateLabel/stateColor, quadrant math, openCStop, setOutputBit.
- Risk:
  - Parallel maintenance and stale variant drift.

5) Usage Map (Key Runtime Paths)

5.1 Startup and wiring
- ui_qml/main.py is the composition root.
- Context properties wired to QML include:
  - RobotComm / RobotCommBridge (bridge)
  - RobotState / RobotCtl
  - ScanDataProvider (from ui_qml.robot_ui.scan_data_provider)
  - WsmService / LogService / UserService / WeldRecordService / LocationService

5.2 Welding scan data flow
- In WeldingScreen.qml:
  - Start Scan path pulses output bit 15, then calls ScanDataProvider.refreshFromRobot().
  - Scan Data path now loads from provider and can fetch when not loaded.
- Fetch implementation path:
  - ui_qml/robot_ui/scan_data_provider.py -> robot_comm/scan_plot_helpers.py

5.3 Robot comm control path
- QML action buttons -> RobotCommBridge slots/methods.
- Bridge drives TCP/EIP setup + UDP cyclic I/O and emits state/io signals to QML/controller.
